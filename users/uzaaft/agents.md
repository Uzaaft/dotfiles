# Preferences

- Be concise and direct. Report the result, relevant validation, and any remaining issue. Skip filler and routine narration.
- Use judgment and finish authorized work. Ask only when ambiguity materially affects the result or you need new authority.
- Keep changes focused. Preserve unrelated work, staging state, and existing commits. Commit or publish only when requested.
- Prefer updating callers and removing obsolete code. Do not add backward-compatibility wrappers, shims, or legacy paths unless explicitly requested.
- Check current source, configuration, or behavior before making claims. Run relevant validation and state any important gaps.
